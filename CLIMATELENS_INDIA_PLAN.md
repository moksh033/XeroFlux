# ClimateLens India — DAV presentation and implementation plan

## Context
ClimateLens India needs visible alignment with the NIErnaya 2026 judges’ Data Analytics & Visualization curriculum without adding a long stack of charts. The requested deliverable is a practical UX recommendation and implementation specification for the four existing analytical pages, purposeful climate colors, statistical explanations, and three-minute pitch hooks. No application changes are part of this planning session.

## Findings recorded during research
- The four root PDFs are three curriculum references (`Data Analytics and Visualization module 1.pdf`, `DAV Module - 02.pdf`, `DAV Lab Programs.pdf`) and the scanned event brochure (`NIErnaya Broucher.pdf`). The brochure could not be extracted/rendered during research; no judging rubric is attributed to it.
- Reuse the existing React/Recharts/Tailwind shell, light/dark themes, MapLibre map, `useFilters`, `QueryState`, `Evidence`, `TrendChart`, `InsightCard`, `SlicerRibbon`, and accessible observation tables. Existing Time Machine, Multi-Hazard, and Sources routes remain intact; do not add a statistical route.
- The prepared manifest and actual API responses supersede stale prose in `backend/README.md` and stale omissions inside `processing_report.json`. Read-only FastAPI requests returned HTTP 200 for temperature by `region=Karnataka` and `region=29`, national drought, and Karnataka/Odisha flood-count comparison for 2007–2016.
- Current rainfall: 2,664 daily state observations over 2026-08-19–2026-11-01, undeclared unit, incomplete year. Current temperature: regional annual summer maximum in °C, 1967–2024. Drought: national annual percentage, 2021–2026. Flood/landslide catalogs span 1967–2023 / 2007–2016. These are manifest declarations, not independent authentication of the upstream sources.
- Current advertised comparison metrics are `flood_event_count` and `landslide_event_count`; annual rainfall is omitted. The actual event-count adapter counts zero documented rows for a state within a catalog-observed year as 0, explicitly not proof of zero hazard. It does not invent globally absent catalog years.
- A live five-variable climate correlation matrix cannot be complete: daily rainfall has no overlapping years with the historical flood/landslide/temperature series, and national drought cannot be assigned to a state. Show the requested five labels with unsupported cells explicitly unavailable; calculate only compatible pairs.
- Installed NIElytics already provides `statistics.summarize`, `quantiles`, `linear_regression`, `correlation_matrix`, IQR outlier reporting, and data-quality profiling. It does not provide continuous histogram binning or the requested pooled two-sample t-test. SciPy is an installed NIElytics dependency; attribute its t-test separately. Do not modify installed library files.
- Existing API scientific outputs are backend/plugin supplied. New DAV calculations must be explicit backend analyses, not silent browser replacements for existing comparison summaries.

## Design direction
Use one primary analytical canvas per page, with in-place view switching and a shared on-demand theory/data provenance panel. Preserve the map as the Atlas hero. Advanced statistical content must expose its sample, assumptions, and unavailable-data states rather than imply unsupported climate conclusions.

## Approved scope choices
Integrate into the four existing pages; do not add a DAV Lab Studio route. Use live observations only: no synthetic examples, teaching fixtures, fabricated matrix cells, inferred rainfall units, or new external data acquisition. Unsupported methods retain a visible explanation of their prerequisites, not a numerical demo.

## Statistical presentation rules
- Distinguish Tukey’s five-number summary (observed min, Q1, median, Q3, observed max) from boxplot whisker endpoints (the most extreme observations inside the 1.5×IQR fences). An outlier is a statistical flag, not proof of a bad measurement or disaster.
- Use the requested histogram rule literally: `k = 1 + ceil(log2(n))`. Show the exact convention in the drawer. Constant samples use one nonzero-width bin and zero valid observations show an empty state.
- Every correlation/scatter point must represent the same state and time grain for both variables; never pair rows by array position, treat missing observations as zero, or label correlation as causation.
- Label the requested pooled two-sided Student t-test as an educational equal-variance model. Annual climate observations may violate independence; show this caveat with the result, not only in hidden theory.
- A non-significant result reads “Fail to reject H₀,” never “Accept H₀” or “The states are equal.” Statistical significance is not climate-policy importance.

## Three-minute demonstration hooks
1. **Explain this outlier** (0:00–0:55): select Karnataka in Atlas, switch rainfall Trend → Distribution, and open the distribution drawer’s boxplot. Focus a flagged observation to reveal its date/value, Q1/Q3, IQR, numeric fences, and the inequality that flagged it. If the selected state has no outliers, show “0 observations outside the fences”; do not manufacture a dramatic dot.
2. **The assumption-aware verdict** (0:55–1:50): compare Karnataka (`29`) with Odisha (`21`) on documented flood counts for 2007–2016. Switch Spread → Test. Show H₀/H₁, sample sizes, pooled SD, df, p-value and precise decision, visibly qualified by count-data, independence, equal-variance and reporting limitations. This is a live-data model calculation, not validated climate-policy evidence; do not promise significance.
3. **Trace the decision** (1:50–3:00): open an actual insight’s evidence chain and its quality audit. Show source records → summary → supported interpretation → proposed decision → proposed action. Finish with the correlation matrix’s honest missing cells: explaining why a result cannot be calculated demonstrates veracity rather than pretending that every variable is comparable. Suggested decisions/actions remain explicitly advisory, never claims of executed interventions.

## Approach

### 1. Provide one explicit backend DAV calculation boundary
Add `backend/app/services/dav_service.py` and `backend/app/services/dav_models.py`; no equivalent typed DAV response exists. Keep `AnalyticsService` and its three-operation plugin protocol unchanged. `DAVService(repository, analytics)` uses prepared records for new descriptive analyses and calls the existing `analytics.execute('compare', parameters)` for comparisons. Never reconstruct or overwrite the existing plugin summary in the browser. Reuse `StrictModel`, `Metadata`, `Envelope`, state validation, chronological `period()` validation and existing error envelopes.

Expose a single GET `/api/v1/dav` in `backend/app/main.py` with `operation: Literal['distribution','comparison','relationship','counts','correlations','audit']`; optional selection arguments are `dataset: Literal['rainfall','temperature','drought','tracks','floods','landslides']`, `state_id`, `state_a`, `state_b`, `metric`, `region`, `storm_id`, `start_year`, `end_year`, `month: Annotated[int | None, Query(ge=1,le=12)] = None`, and `measure: Literal['value','wind','pressure'] = 'value'`. Retain existing Year/StateID constraints. Validate operation-specific requirements below; return 422 `UNSUPPORTED_ANALYSIS` for incompatible selections, 404 for unknown state/storm, existing 503 dataset errors for unavailable files, and `no_data` with data=null for valid empty selections. No silent fallback to another dataset.

Use `Result[DAVPayload | None]` with `DAVPayload = Annotated[DistributionPayload | ComparisonDAVPayload | RelationshipPayload | CountsPayload | CorrelationsPayload | AuditPayload, Field(discriminator='kind')]`; each payload has its corresponding `kind: Literal[...]`, `reason: str | None`, and fields below. All listed computed scalar summary/regression/test/numeric-audit statistics are individually typed `float | None`, including min/max, percentiles, fences and whiskers; counts are integers. All non-finite results become null with an explanatory limitation, never NaN/Infinity. Envelope metadata carries actual source IDs, selected period, unit, executed method and limitations. New exact response shapes:

- `SamplePoint = {id: str, label: str, value: float}`. Source identity/label is state+date for rainfall, region+year+month for temperature, year for drought, storm+timestamp for tracks, and state+year for comparison series. Preserve source identifiers, never use a plot index as identity.
- `Distribution = {n: int, missing: int, mean, median, variance, std, min, p10, q1, q3, p90, max, iqr, lower_fence, upper_fence, whisker_low, whisker_high, bowley, kelly, excess_kurtosis: float | None, kurtosis_class: 'leptokurtic' | 'mesokurtic' | 'platykurtic' | null, bins: [{lower: float, upper: float, count: int}], outliers: SamplePoint[]}`. Undefined-statistic explanations go in envelope limitations; zero denominators must be named.
- `Regression = {n: int, slope, intercept, r, r_squared: float | None, reason: str | None}`; `PairPoint = {id: str, label: str, x: float, y: float}`.
- `Test = {n_a: int, n_b: int, mean_a, mean_b, variance_a, variance_b, pooled_sd, t, p_value: float | None, df: int | None, alpha: 0.05, decision: 'reject' | 'fail_to_reject' | 'unavailable', reason: str | None}`.
- `distribution`: `{points: SamplePoint[], summary: Distribution}`.
- `comparison`: `{comparison: ComparisonResult, a: Distribution, b: Distribution, points: PairPoint[], regression: Regression, test: Test}`. Return the original `ComparisonResult` unchanged.
- `relationship`: `{points: PairPoint[], regression: Regression, x_label: str, y_label: str, x_unit: str | None, y_unit: str | None}`; nullable unit defaults are None.
- `counts`: `{rows: [{hazard: 'floods' | 'landslides', decade: int, count: int | None, reason: str | None}], excluded_undated: int}`.
- `correlations`: `{variables: ['rainfall','floods','landslides','temperature','drought'], cells: [{x: str, y: str, n: int, r: float | None, reason: str | None, points: PairPoint[], regression: Regression}]}`.
- `audit`: `{scope: 'filtered_prepared_records', rows: int, columns: [{name: str, dtype: str, missing: int}], duplicate_rows: int, duplicate_identities: int, numeric: [{name: str, count: int, mean, median, variance, std, min, max: float | None}]}`.

Generate contracts using `backend/export_openapi.py`, then `npm run generate:api` from `frontend/`; add DAV response aliases in `frontend/src/api/types.ts`. Do not hand-edit `schema.d.ts` or encode nested chart data as JSON strings in `Insight.statistics`.

### 2. Implement calculations and sample selection before exposing new views
Use a shared `DAVService.execute(operation: str, parameters: dict) -> Envelope` dispatcher and private helpers in the new service. Selection, computation, and presentation must agree on the same sample:

- **Distribution:** `rainfall` requires `state_id`; `temperature` requires `region` using the exact requested region representation (do not concatenate code and name aliases); `drought` rejects `state_id` and is national only; `tracks` requires `storm_id` and `measure=wind|pressure`. Filter years and optional temperature month before computation; honor current `ReturnedSeries` year-only/month-specific separation. Source rows with null measurement stay counted as missing, not zero.
- **Summary:** call NIElytics `statistics.summarize(..., ddof=1)` and `statistics.quantiles(..., q=[.1,.25,.5,.75,.9])`; quantiles use linear interpolation as Pandas does. `IQR=Q3-Q1`; fences are Q1−1.5IQR and Q3+1.5IQR. Use NIElytics IQR outlier detection and retain the corresponding original points; strict inequalities flag points outside the fences. Whiskers stop at actual in-fence extrema. If IQR=0, keep valid fences and outlier flags, but Bowley is unavailable.
- **Histogram:** no continuous-binning equivalent exists in NIElytics. Calculate `k=1+ceil(log2(n))` equal-width bins from observed min/max; left-closed/right-open except the final bin includes max. Show all bins, including zero-frequency bins. For a constant value v use one bin `[v−w/2,v+w/2]`, `w=max(1,abs(v)*.01)`; one observation has an ordinary one-bin display but variance/std/kurtosis unavailable. Empty samples return `no_data`.
- **Shape:** Bowley `(Q3+Q1−2*median)/(Q3−Q1)`; Kelly `(P90+P10−2*median)/(P90−P10)`. Zero denominators produce null with explanatory drawer copy. Use the library’s Pandas unbiased Fisher excess kurtosis; it is unavailable for n<4 or constant samples. Classify its displayed sign using a ±0.05 near-zero band: `abs(g2)<=.05` is “approximately mesokurtic,” above .05 leptokurtic, below −.05 platykurtic. State that this is a descriptive display convention, not a normality test. Do not infer extreme-disaster risk from the class.
- **Comparison:** require distinct states, start/end and a metric actually advertised by the backend. Call the existing compare operation and retain all its coverage/error behavior. Derive both distributions from its actual annual series. Scatter points join by explicit year; use NIElytics `linear_regression(frame,'x','y')`, mapping `r_value` to `r` and `r_squared` unchanged. Require ≥3 complete pairs and variation in both axes; otherwise return points with unavailable coefficients and a specific reason. No extrapolated line beyond the observed x range.
- **Pooled test:** compute over each state’s returned annual observations, not the all-years summary total. Use sample variances: `sp²=((nA−1)sA²+(nB−1)sB²)/(nA+nB−2)`, `t=(meanA−meanB)/(sp*sqrt(1/nA+1/nB))`, `df=nA+nB−2`, `p=2*scipy.stats.t.sf(abs(t),df)`. Require nA,nB≥2 and positive pooled variance; otherwise unavailable, not artificial p=0/1. Reject H₀ iff p≤.05. Attribute this formula/SciPy calculation to ClimateLens DAV, not an upstream NIElytics t-test. Count metrics have a permanently visible “Assumption-dependent model on documented counts; independence/equal variance not established; reporting differs” note. Same-year observations can be cross-correlated; do not claim the independent model is empirically validated or silently switch to a paired/Welch test.
- **Cyclone relationship:** use the selected storm’s same-timestamp wind/pressure pairs with declared, consistent units. Retain track observations missing one measurement in the source table but exclude them from pairs; show excluded count via metadata limitations. Reject mixed units rather than convert implicitly. Use the same regression helper and temporal-dependence caveat.
- **Counts:** require year bounds; `state_id` is optional. Missing `state_id` means all catalog rows including unassigned events, matching Explorer Records. With a state, filter by its exact ID. Read complete prepared flood and landslide records, never a paginated API page. Group dated rows by `hazard` and `decade=floor(year/10)*10`. Include decades with any selected dated row. For a hazard with catalog-observed years inside the selected bounds/decade, zero means zero selected documented rows, not zero hazard. If that hazard has no globally observed catalog year in the decade/bounds, return count=null with “No catalog coverage in this period,” not zero. Never fabricate whole empty years. Report undated rows for the selected geography as excluded before year filtering; their period is unknown. Do not compare basin storm counts to state incident counts.
- **Correlations:** require state/year bounds. Keep all five requested labels. For annual state temperature, select `region == state_id` and `month is None` only; require the declared annual resolution and unique `(region,year)` identities. If annual state-code rows are absent, return a temperature unavailable reason rather than guess from name aliases; duplicate year identities also make that variable unavailable. Build documented annual flood/landslide counts using the exact catalog-observed-year convention in `_compare_event_counts`; retain that limitation. Align pairs by explicit year/state; require ≥3 nonconstant complete pairs. Use NIElytics `correlation_matrix(method='pearson')` and the same regression helper; include pairwise n and observed years in point labels/tooltips. Daily rainfall is not promoted to annual rainfall: its cells read “Daily observations; annual total not available.” National drought cells read “National series cannot be assigned to this state.” No diagonal1 for unavailable variables. Current temperature/floods/landslides can form a descriptive three-variable submatrix for 2007–2016; rainfall/drought remain unavailable.
- **Audit:** select the same dataset/state/region/storm/period as the active chart. Compute `isnull().sum()`, exact duplicate rows and observation-identity duplicates on the complete filtered prepared table; normalize nested attributes for whole-row duplicate comparison. Reuse NIElytics profiler and `summarize`, including sample SD/variance. Count measurement zero as present. Explicitly label the scope “Prepared records; excluded source rows are not included.” Do not relabel ingestion `blank_numeric` counters as `isnull().sum()` or assert that preprocessing had no duplicates because prepared rows do not.

There is no typed DAV calculation service in the current application; only these small orchestration/binning/shape/test helpers are new. Reuse installed numerical routines rather than implement probability distributions or a second general-purpose statistics library.

### 3. Build one reusable analytical surface, not a dashboard kit
Add `frontend/src/components/DAVPanels.tsx` for `AnalysisTabs`, `DistributionPanel`, `SpreadPanel`, `RelationshipPanel`, `TestPanel`, `CorrelationPanel`, `CountPanel`, and `AuditPanel`, all rendering the corresponding generated payload type. Add `frontend/src/components/AnalysisDrawer.tsx` for a controlled `AnalysisDrawer({open,onClose,title,children})`. No equivalent statistical components exist; keep existing `TrendChart` and ordinary page callers unchanged.

- Reuse `.chart-canvas`, neutral panel chrome, existing token/focus styles, `QueryState`, `Evidence`, and the accessible table disclosure. Chart view switching uses a compact segmented control (6–8px radius, not floating pills everywhere). `AnalysisTabs` takes `{label, options: {id,label,disabled?}[], value, onChange}` and uses `role=tablist`, roving tab index, arrow/Home/End keys, selected tab/panel IDs. Unlike `SlicerRibbon`, clicking the active view never deselects it. Reuse `SlicerRibbon` unchanged for actual hazard/decade filters.
- Persist active view as hash query `dav_view`; each page accepts only its named views and falls back to its default when a carried-over value is unsupported. Use `distribution`/`trend`, `counts`/`records`, `relationship`/`track`, `trend`/`spread`/`relationship`/`test`, and `findings`/`correlations` as appropriate. Preserve geography/period/metric on view change. Keep matrix selected pair and open drawer local; discard pair selection when scope changes. No new global store.
- Maintain analysis-body height 280px in a state rail and 360px in a full workbench. Tall test/audit/table contents scroll within that body; view switching does not move surrounding content. Method/quality content scrolls inside the drawer, not below appended charts. Desktop drawer width is `min(480px,100vw)`; mobile is a full-screen dialog with internal scrolling and a persistent close control. Ordinary page flow may scroll on small screens; do not force the map into a tiny fixed-height mobile viewport.
- Use native modal `<dialog>` with a descriptive heading, initial focus on Close, Escape handling and focus return to opener. Native modal behavior makes underlying navigation/assistant controls inert; do not introduce a global overlay event bus. Backdrop closes only on direct backdrop activation, not clicks inside the panel.
- Histogram: Recharts `BarChart` with numeric bin ranges, frequency y-axis from zero, adjoining bins, and `ReferenceLine` mean/median with solid/dashed label cues. Numeric x positions must correspond to the bin geometry; do not place the mean by categorical bin index. Tooltip: numeric interval, inclusion convention, count, percentage, n, chosen k and Sturges formula. If mean and median labels overlap, combine their legend and keep exact values in the tooltip/summary.
- Boxplots: one small responsive SVG rendering backend coordinates into a common numeric axis, with title/description and an equivalent table. Recharts has no native statistical boxplot; do not misuse a stacked bar chart as one. Outliers are keyboard-focusable hollow diamonds; tooltip uses actual value/date and numeric fence inequality, e.g. `value > Q3 + 1.5×IQR = upper_fence`. Expose observed min/max separately from whiskers.
- Scatter: Recharts `ScatterChart`; regression line uses backend slope/intercept solely to position two line endpoints at observed min/max x. Show `y = mx + c`, `r`, `R²`, n and axis units. Hover/focus shows source identity, x/y, fitted value and residual; geometry arithmetic must not become a replacement statistical estimator.
- Test: not another chart. Show H₀: μA=μB, H₁: μA≠μB; compact aligned rows for n, mean, SD, pooled SD, t, df, p, α and decision, plus one sentence explaining the result under assumptions. Show full precision on focus; format small p as `<0.0001` rather than `0.0000`. A p-value is not the probability H₀ is true. Display `variance` as `s²` and `std` as `s`, with units.
- Correlation matrix: use an accessible HTML table with button cells rather than adding a chart library. Annotate each numeric cell to two decimals with pairwise n in tooltip/focus details; fixed centered legend −1/0/+1. Hatch N/A and allow opening the exact unavailable reason. Clicking a numeric off-diagonal cell opens its backend-supplied pair scatter in the same canvas with Back to matrix. No dual display of matrix and scatter; constant/insufficient samples stay unavailable.
- Counts: a Recharts categorical `BarChart`, not a histogram. One segmented control `Count plot / GroupBy / Pivot` swaps representations. Count plot alone has a `Group by` select (`Hazard` or `Decade`). GroupBy lists the backend `(hazard,decade,count)` rows with `DataBar`; Pivot uses decade rows and flood/landslide columns. Every representation uses the identical backend grouped rows. Label counts “Documented catalog records”; active-hazard highlighting must not silently filter out the other hazard or change the sample between representations.
- Keep the existing source observation table accessible alongside every visual. New summary/bin/pair tables describe derived values and are labeled separately. Do not delete source evidence to achieve first-fold density.
- The drawer's Data & assumptions section always has a “Quality audit” action. Atlas/Explorer use the exact active dataset selection; Comparison offers State A / State B and audits that state's underlying prepared source records, explicitly distinct from the derived annual series; Insights offers the active source dataset. Audit identity keys are rainfall `(state_id,year,date)`, temperature `(region,year,month)`, drought `(year)`, tracks `(storm_id,timestamp)`, and event catalogs `(event_id)`. Do not audit only a rendered page or concatenate state-name/code aliases.

### 5. Make the foundations visible on demand
Inside the shared drawer's “Platform & syllabus” tab, link to existing Sources, not a new route:

- **Four analytics types:** descriptive = observed distributions/counts; diagnostic = exploratory relationships with “association, not established cause.” Predictive is “Not implemented: historical fit is not a forecast”; prescriptive is “Human-reviewed recommendation, not optimized or automated intervention.” Do not rename an OLS fit “Predictive” to tick a syllabus box.
- **Decision chain:** use the Module 1 p. 12 sequence and bind highlighted stages to the selected insight as above.
- **Data types:** structured tables and time series; semi-structured GeoJSON/API event attributes; unstructured documents/free-text only where actually present. Incident rows with fixed fields are not inherently unstructured.
- **5Vs:** Volume = actual catalog record counts; Velocity = batch prepared workbook, not live streaming; Variety = actual file/record types; Veracity = missingness, duplicates and source limitations; Value = the concrete insight/report. Avoid claiming distributed big-data infrastructure.
