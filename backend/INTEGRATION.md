# Backend / science / frontend integration

## Shared API contract

`contracts/openapi.yaml` is generated by `backend/export_openapi.py` from FastAPI/Pydantic. `/openapi.json` and `/docs` expose the same running contract. Regenerate after changing public models/routes. Frontend can generate TypeScript without editing this backend:

```powershell
# From frontend, after the backend contract exporter:
npm.cmd run generate:api
```

Use `http://127.0.0.1:8000/api/v1` for the documented local run command. The frontend now has generated types, real queries and live data views; Vite proxies same-origin `/api` to this server. For separate-origin deployments configure `VITE_API_BASE_URL` to the complete API prefix and allow the frontend origin in `CLIMATELENS_CORS_ORIGINS`. See `../frontend/README.md`.

Success observations: `{status: 'ok', data, meta}`. Valid unmatched observations: `status: 'no_data'`, empty array (or empty page items); comparison and DAV no-data use `data: null`. DAV no-data still carries complete metadata with observation count 0 and limitations. `meta.observation_count` counts observations for that operation, not total disasters; paginated `data.total` is matching available records. An offset beyond the collection returns an empty page, not measured zero. Ordinary observation periods cover returned source labels; DAV metadata also preserves explicit selected year bounds. Event records without timestamps keep available years only. Metadata has source IDs, declared units/geographical/temporal level, method and limitations. Missing dependency is HTTP 503 `{error:{code,message,details}}`, not `no_data`.

Record IDs are opaque strings. Join rainfall and boundary properties through verified `state_id` only, never name guesses. Boundary coordinates are longitude/latitude in EPSG:4326; the preparation CLI reprojects official NWIC EPSG:7755 geometry with pyproj and preserves islands/holes. Rainfall returns values without geometry. Select an actual `capabilities.rainfall_observation_dates` using `observation_date`; ambiguous multi-date state/year requests return `OBSERVATION_DATE_REQUIRED`, not an inferred annual total. Current rainfall unit is null because the workbook does not declare it. No-data styling must differ from measured zero. Drought remains national annual percentage; temperature is currently regional annual summer maximum in °C, with month selection only for actual returned monthly records. Basin cyclone coverage is not Indian landfall.

## Prepared-storage contract (new backend convention)

No processed files were supplied initially. Manual preparation CLIs normalize supported workbook source fields and separately reproject official NWIC geometry. Provenance/omission reports accompany observations. Current manifest declarations supersede stale earlier processing-report omissions: rainfall has 2,664 daily state rows for 2026-08-19–2026-11-01 with unit null; regional annual summer maximum temperature spans 1967–2024 in °C; national annual drought-area percentage spans 2021–2026. Flood/landslide catalogs span 1967–2023 / 2007–2016. These are prepared/provider declarations, not independently authenticated source coverage or newly executed verification. Annual rainfall totals/anomalies remain unsupported; raw column positions and missing units are not guessed.

`manifest.json` structure:

- `version`: integer `1`.
- `processed_at`: actual processing timestamp string.
- `metadata`: catalog `Metadata` object (not a climate metric copied from one dataset).
- `sources`: `Source[]` with unique actual IDs and provider/source URL/provenance details.
- `capabilities`: declared supported controls; `comparison_metrics` is the list of advertised comparable metric IDs, currently `flood_event_count` and `landslide_event_count`. Their documented-count interpretation does not establish independent/equal-variance samples or hazard-risk comparability. Other capability keys convey supported years/regions/coverage; frontend must not infer scientific validity from file existence.
- `datasets`: object keyed by the dataset names below. Each value has `path`, `format`, `meta`.

`Metadata` fields: `metric`, nullable `unit`, `geographic_level`, `time_resolution`, `period:{start,end}` (nullable strings), `source_ids`, nullable `method`, nonnegative `observation_count`, `limitations`. These are actual declared source/calculation facts, not arbitrary presentation values. Every source ID must exist in the catalog.

`Source` fields: `id`, `name`, `provider`, nullable absolute HTTP(S) `url`, `geographic_coverage`, `temporal_coverage`, `data_format`, `purpose`, `provenance_status`, `limitations`.

Dataset paths must be relative and confined inside the prepared-data root; absolute/traversal paths and symlink escapes are rejected. Formats: `parquet` (`.parquet`), `json` (`.json`) and `geojson` (`.geojson`). JSON record datasets are bare arrays; boundaries are a FeatureCollection. No public file path is accepted in API queries. Missing/invalid files are explicit errors, and the cache is invalidated by file signature changes. Prepared tables are loaded and validated on first use and cached; for very large archives partition/export appropriate demo datasets rather than relying on this cache as a full database engine.

Required row schemas (extra fields rejected; event attributes belong in `attributes`):

| Dataset | Record fields / scope |
| --- | --- |
| `states` | `state_id`, `name`; state-level geographic catalog |
| `boundaries` | FeatureCollection of Polygon/MultiPolygon; each feature has `properties.state_id`, `properties.name` matching states; closed valid-range rings |
| `rainfall` | `state_id`, `year`, nullable ISO `date`, `value`; daily records preserve dates, annual records require explicit compatible metadata |
| `drought` | `year`, `value`; `meta.geographic_level = national` |
| `temperature` | `region`, `year`, nullable `month`, `value`; `meta.geographic_level = regional` |
| `floods`, `landslides` | `event_id`, nullable `state_id`, nullable `year`, nullable `timestamp`, nullable coordinate pair `longitude`/`latitude`, `attributes` object |
| `cyclones` | `storm_id`, `name`, `year` |
| `tracks` | `storm_id`, timezone-aware source `timestamp`, `longitude`, `latitude`, nullable `wind`, `pressure`, `wind_unit`, `pressure_unit` |

Source intensity measurements require their source units. Event years and timestamps must agree. Preserve unavailable dates/coordinates as null; do not synthesize them. All numeric measurements must be finite. Source absence alone is not measured zero: the documented event-count policy below permits zero selected records only within globally catalog-observed coverage.

## Analytics plugin protocol (not an upstream NIElytics signature)

The included default `app.services.nielytics_adapter` calls actual pinned NIElytics 0.2.0.dev1 APIs. A custom science adapter selected by `CLIMATELENS_ANALYTICS_MODULE` must expose:

```python
def analyze(*, operation: str, parameters: dict, repository):
    # Call the actual NIElytics/data-team implementation here.
    # Return the documented Envelope-compatible structured result.
    ...
```

This protocol is a ClimateLens boundary, not an upstream NIElytics signature. The delivered adapter invokes actual summaries, Mann–Kendall, event aggregation, InsightEngine and regional catalog overlap. Current daily rainfall cannot satisfy annual-rainfall preconditions; supported event insights remain available with that limitation. Imports use trusted local configuration, never user query parameters. No synthetic fallback or external LLM is used.

Operations:

- `compare`: parameters `state_a`, `state_b`, `metric`, `start_year`, `end_year`. Allowed candidate metrics: `rainfall_annual_total`, `rainfall_anomaly`, `flood_event_count`, `landslide_event_count`; only manifest-declared supported metrics are enabled. The plugin must enforce same definitions/units/resolution/common observation periods, sufficient coverage and valid missing-data handling. Backend validates returned identity/metric/period and result structure; it cannot certify the unseen scientific implementation.
- `insights`: `state_id`, optional paired `start_year`/`end_year`. Deterministic facts/explanations must come from actual NIElytics executions. No external LLM is used.
- `multi_hazard`: same filters; return validated relationships with individual records/sources and explicit noncausal limitations. Do not infer causation from overlap.

Exact output models are in `app/services/analytics_models.py` and OpenAPI. `Insight.period` is its time period and `Insight.method` is its methodology; computed value, unit, geographic resolution, observations and sources must reflect actual calculations. Comparison values and differences are supplied by the plugin, never calculated in routes. Null percentage is required when its declared baseline is zero. A plugin producing invalid/unprovenanceable data fails explicitly, never degrades to fabricated values. Empty valid analytics uses documented `no_data` with an explanation in limitations.

## DAV service and generated contract

GET `/api/v1/dav` uses `DAVService(repository, analytics).execute(operation, parameters)`, separate from the unchanged three-operation analytics plugin. Its `operation` is `distribution`, `comparison`, `relationship`, `counts`, `correlations` or `audit`. Optional route selectors are `dataset` (`rainfall`, `temperature`, `drought`, `tracks`, `floods`, `landslides`), `state_id`, `state_a`, `state_b`, `metric`, `region`, `storm_id`, `start_year`, `end_year`, `month` (1–12) and `measure` (`value` by default, `wind`, `pressure`). Each operation accepts only compatible selectors; bounds must be supplied together and ordered. Comparison, counts and correlations require bounds.

| Operation | Required selection / sample | Discriminated payload |
| --- | --- | --- |
| `distribution` | `dataset`; rainfall requires `state_id`, temperature an exact `region`, national drought no state, tracks `storm_id` plus `measure=wind` or `pressure`; optional year bounds / temperature month | `kind=distribution`, source-identified `points`, `summary` |
| `comparison` | Distinct `state_a`, `state_b`, advertised `metric`, year bounds; actual returned annual observations | `kind=comparison`, unchanged original `comparison`, distributions `a`/`b`, year-joined `points`, `regression`, `test` |
| `relationship` | `storm_id`, optional `dataset=tracks` / bounds; identical storm/timestamp complete wind-pressure pairs, default `measure=value` | `kind=relationship`, `points`, `regression`, `x_label`, `y_label`, nullable `x_unit` / `y_unit` |
| `counts` | Year bounds, optional exact `state_id`; complete flood and landslide catalogs, all rows including unassigned events when state omitted | `kind=counts`, hazard/decade `rows` with nullable `count` and `reason`, `excluded_undated` |
| `correlations` | `state_id`, year bounds; compatible annual state/year observations | `kind=correlations`, five `variables`, pairwise `cells` containing `n`, nullable `r`, `reason`, `points`, `regression` |
| `audit` | Same source dataset/state/region/storm/bounds/month as active analysis; rainfall/temperature/tracks require their distribution geography identifiers | `kind=audit`, `scope=filtered_prepared_records`, `rows`, column dtypes/missingness, `duplicate_rows`, `duplicate_identities`, numeric summaries |

Every payload also has nullable `reason`. `Result[DAVPayload | None]` is a `kind`-discriminated union in FastAPI/OpenAPI. Computed scalar statistics are nullable individually: undefined/non-finite results are null with limitations, never NaN/Infinity. Valid empty selections return `no_data`/`data:null`, not a substitute dataset. Incompatible selectors or unsupported DAV metrics return 422 `UNSUPPORTED_ANALYSIS`; route value/range validation and invalid periods also return 422. Unknown verified state/storm IDs return 404; unavailable/invalid prepared files retain existing 503 errors.

Export with `.venv/Scripts/python.exe export_openapi.py` from `backend/`, then `npm.cmd run generate:api` from `frontend/`. Do not hand-edit `src/api/schema.d.ts`. `src/api/types.ts` aliases generated `DAVQuery`, `DAVPayload`, all six payloads, `Distribution`, `SamplePoint`, `PairPoint`, `Regression` and `Test`. Existing `getApi` / `useApi('/api/v1/dav', query, undefined, enabled)` use generated `paths` types and parameterized query keys; nested chart payloads are not strings in `Insight.statistics`.

### Grain, methods and unavailable values

- Rainfall retains state/date identity; the recorded-date map KPI does not shorten a separately selected period distribution. No annualization or inferred millimetres. Temperature uses exact region/year/month identities, never concatenates name/code aliases, and excludes year-only rows from a selected-month sample. Drought retains national/year identity. Numeric null is missing; numeric zero is present.
- NIElytics supplies `summarize(ddof=1)`, linear quantiles, strict 1.5×IQR outlier flags, OLS, Pearson correlation and profiling. ClimateLens DAV supplies `k=1+ceil(log2(n))` equal-width histogram bins, left-closed/right-open except final inclusion of max; zero-frequency bins remain. Constants use one nonzero-width bin, without fabricated spread. Whiskers are actual in-fence extrema, distinct from observed min/max. Bowley/Kelly zero denominators are unavailable. Unbiased Fisher excess kurtosis needs at least four nonconstant observations; the ±0.05 approximately-mesokurtic band is descriptive, not a normality or risk test.
- Comparison calls `analytics.execute('compare', parameters)` and preserves its `ComparisonResult` unchanged. New statistics use its actual annual series, not all-years totals. Scatter joins explicit years, never array positions. OLS/correlation needs at least three complete pairs and variation in both axes; otherwise pairs remain available with null coefficients and a reason. Lines do not extrapolate beyond observed x.
- The educational pooled equal-variance two-sided Student t-test is **ClimateLens DAV using SciPy**, not an NIElytics test: `sp²=((nA−1)sA²+(nB−1)sB²)/(nA+nB−2)`, `t=(meanA−meanB)/(sp*sqrt(1/nA+1/nB))`, `df=nA+nB−2`, `p=2*scipy.stats.t.sf(abs(t),df)`. Require nA,nB≥2 and positive finite pooled variance; otherwise unavailable, not artificial p=0/1. Reject H₀ iff p≤0.05. No silent paired/Welch substitution.
- Annual climate observations may be temporally dependent and same-year observations cross-correlated. Count results retain “Assumption-dependent model on documented counts; independence/equal variance not established; reporting differs”. “Fail to reject H₀” does not establish equal states; a p-value is not P(H₀ true), and significance is not policy importance.
- Cyclone relationships retain storm/timestamp identity and declared consistent units; mixed/undeclared measurement units are rejected rather than converted implicitly. Incomplete measurement rows stay in source records, are excluded from pairs, and are disclosed in limitations. Storm observations may be temporally dependent; association is not causation.

### Complete catalog coverage and prepared-only audit

Counts read complete prepared flood/landslide tables, not paginated event responses. Dated selected rows are grouped by hazard and `decade=floor(year/10)*10`; include decades containing selected dated rows. For each hazard/decade/bounds intersection, globally catalog-observed years permit 0 selected documented rows. No globally observed year means `count:null`, reason “No catalog coverage in this period”, not zero. Annual comparison/correlation count series likewise use only globally catalog-observed years (for example, the current flood catalog has no 1977); absent whole years are never fabricated. Counts are not risk and reporting completeness differs. Count exclusions include all undated rows for the selected geography **before** year filtering because their period is unknown.

The correlation matrix retains rainfall/floods/landslides/temperature/drought. Rainfall cells say “Daily observations; annual total not available.” Drought cells say “National series cannot be assigned to this state.” These unavailable variables get no artificial diagonal 1. Temperature requires declared annual resolution, exact `region == state_id`, `month is None` and unique `(region,year)` identities; no alias guessing or duplicate-year aggregation. Compatible annual temperature/flood/landslide cells use pairwise complete explicit-year joins, pairwise n and actual years; unsupported/constant/insufficient cells expose reasons rather than fabricated r.

Audit reads the complete filtered prepared source table, not visible rows, histogram bins, matched pairs or derived annual counts. Comparison audits select State A or B's underlying prepared source. It reports actual `isnull().sum()`, dtypes, numeric sample summaries, nested-normalized exact-row duplicates and identity duplicates: rainfall `(state_id,year,date)`, temperature `(region,year,month)`, drought `(year)`, tracks `(storm_id,timestamp)`, events `(event_id)`. **“Prepared records; excluded source rows are not included.”** Ingestion `blank_numeric` counters are not prepared missingness; no upstream duplicate/completeness/authenticity claim follows from this audit.

## Reporting and judging

Reports render supported prepared rainfall/event rows and available verified insight output, not newly calculated summaries. Source definitions/methods/limitations and generation date accompany observations. No reportable records means `REPORT_UNAVAILABLE`, never a generic blank PDF. Browser clients must check HTTP success and PDF content type before saving.

Use `/metadata` for actual dates/years/capabilities and `/sources` for lineage. Supported prepared events, tracks, daily rainfall, national drought and regional annual temperature retain their declared limitations; official geometry is prepared separately. The frontend consumes generated types and the DAV service in its existing four analytical pages; Time Machine, Multi-Hazard and Sources remain separate existing routes. Annual rainfall/state drought and incompatible correlation cells remain unavailable by design. Historical HTTP/PDF smoke outcomes are in `VERIFICATION.md`; new integrated DAV/browser results must be recorded only after they are exercised.
